# 判定规则（v1 现状）

一句话：**一条结论能不能算「结论」，取决于它有页码、落在对的表里、判定值在四个取值内；三件事分别由代码、模型、人负责。**

本文对应现有代码（`tender/tables.py`、`workflow.py`、`tools.py`、`eval/compare.py`），不是目标态；v2 会改的地方在最后一节。

---

## 一、判定值只有四个

`Verdict = Literal["满足", "不满足", "人工看", "无须提供"]`（`tables.py:10`）

| 取值 | 含义 | 谁给的 | 能出现在 |
|---|---|---|---|
| **满足** | 按这份 `company.yaml`，这条能过 | 模型对照 YAML | 废标对照、材料对照 |
| **不满足** | 按 YAML，这条过不了（会废标 / 缺材料） | 模型对照 YAML | 废标对照、材料对照 |
| **人工看** | 判不了：没有页码、条款含糊、★ 待确认 | 代码（无页码时强制）+ 模型 | 废标对照、材料对照 |
| **无须提供** | 招标方代查、或本项目不收，不需要公司提供 | 模型 | 材料对照 |

没有第五个值。想表达「不知道」只能用「人工看」，**不允许留空**。

## 二、六张表：字段与判定口径

| 表 | 关键字段 | 有 verdict 吗 | 判定在说什么 | 谁判 |
|---|---|---|---|---|
| **废标对照** `FeibiaoRow` | condition / company / verdict / star / refs | 有（必填，默认人工看） | 「以这家公司的条件，这条会不会导致废标」 | 模型对照 YAML；无页码时降级人工看；★ 由代码补行 |
| **评分对照** `PingfenRow` | item / score / standard / company / estimate / refs | **没有** | 不判对错，只写「能拿多少分」的预估；主观分写「主观分，不预估」 | 模型填 estimate |
| **材料对照** `CailiaoRow` | material / company / verdict / refs | 有 | 「这份证明材料公司有没有」；招标方代查的标无须提供 | 模型对照 YAML；无页码降级 |
| **空位对照** `KongweiRow` | form / field / note / refs | **没有** | 只列「这张表要填哪些格子」，不代填 | 模型列举 |
| **时间节点** `ShijianRow` | name / when / note / refs | **没有** | 纯事实：截止、开标、质疑期限 | 模型抄原文 |
| **合同要点** `HetongRow` | item / content / note / verdict（可选）/ refs | 可选，一般空 | 纯事实；履约保证金只许落在这里 | 模型抄原文 |

口径上的三条推论：

1. **只有两张表在「下判断」**，其余四张是事实搬运。评测里那四张只能验「在不在、页码对不对」，验不了判定质量。
2. **评分表不判「拿不拿得到」**，只估分；不要拿它当及格线用。
3. **合同要点带一个可选 verdict 字段**，但没人填，也参与不了判定——现状是留给以后的，不当判定依据。

## 三、谁判：三方分工

### 代码判（确定性，不可协商）

| 动作 | 位置 |
|---|---|
| 四步核对的检索范围（废标=邀请+须知+资格；评分=评标办法；材料=须知+资格+格式；空位=格式；时间=邀请+须知；合同=合同+格式） | `workflow.py:134 / 169 / 197 / 214 / 239-248` |
| 没有页码 → 强制「人工看」（只作用于废标、材料两表） | `tables.py:92` + `workflow.py:_stamp_pages` |
| 废标表排序：★ 在前，其次「不满足」 | `workflow.py:161` |
| ★ 正则补一行占位（`condition` 写「带 ★ 的实质性条款（正则命中，待确认是否不满足即无效）」，`verdict` 固定人工看，只补第一条） | `workflow.py:147-158` |
| 价格分计算（基准价 / 报价 × 满分，不让模型口算） | `tools.py:77` |
| 题集打分（hit / miss / absent / violated） | `eval/compare.py` |

### 模型判（语义，必须留出处）

- 从检索段落里抽字段、判断这段在讲什么（`_extract`）；
- 对照 `company.yaml` 给 `满足 / 不满足 / 人工看`；
- 评分表写 `estimate`、材料表判「有没有」；
- 提问框里选工具和章节，资料不够就答「文件中未找到」（`ask_box.py:10-16`）；
- **`star` 字段也由模型自己填**——这是现状的漏洞，见第六节。

### 人判（兜底，不能被模型覆盖）

- 所有 `人工看` 的行，由人给最终结论；
- ★/▲ 条款「是不是不满足即无效」，现状一律人工确认（正则不认定语义）；
- 对模型给出的 `满足 / 不满足` 改判（v2 才有改判记录，现在只改结果不留痕）。

## 四、五条硬规则

1. **每行必须带出处**：`refs` 里每条是 `{page, chapter, clause, text, bbox}`；`page` 不可空，`bbox` 可空。没页码就不是正式结论。**页码一律指 PDF 物理页**（第 1 页为封面），不是页脚印刷页码——beijing、chongzuo 两者差 2 页，wenling 一致；要展示给用户时另外换算，不能改这里的值。
2. **检索范围由代码给，模型不能自己扩**：四步核对里模型只看得见指定章节的命中（`index.py:143` 按类型查库）。提问框是例外，模型可以自己选章节，但每次只能选一个已知类型。
3. **不编造**：`company.yaml` 里没有的证书、业绩、人员不得出现在表里；判不了就写人工看。
4. **投标保证金 ≠ 履约保证金**：后者是中标后约束，只进合同要点，进废标表就是错（题集里有负例 `bj-neg-perf-bond`、`cz-neg-perf-bond`、`wl-neg-perf-bond` 专门抓它）。
5. **★/▲ 行排最前**，且必须能回指到原文标记所在页。

## 五、评测用的判定口径（`eval/compare.py`）

题集 21 条：正例 18、负例 3、断言判定值 12 条（`eval/questions.json` 的 `expect_verdict`）；其余 6 条落在无判定字段的表上，清单里标「不适用」。

清单（`eval/题集核对清单.md`）和题集（`eval/questions.json`）必须口径一致：同一个 id 的期望表、期望页、期望判定、正负例，两边逐条相同。这条由 `tests/test_eval_consistency.py` 守着，改一边不改另一边会红。

| 概念 | 定义 |
|---|---|
| 候选 | 落在题面 `tables` 允许的表里、正文含 `keyword` 的条目 |
| 正例 hit | 某条候选的页码命中 `expect_pages`，且（若题面给了）`verdict` 落在 `expect_verdict` 里 |
| 正例 miss | 有候选但都不满足上述条件；`reason` 区分 `page`（页码就不对）和 `verdict`（页码对、判定错） |
| 正例 absent | 这些表里压根没有这条 |
| 负例 hit | 该表确实没出现关键词 |
| 负例 violated | 关键词混进了不该出现的表 |

另有独立指标（不进分数）：`eval/markers.json` 记原文 ★/▲ 个数与所在页，`compare.py` 报「原文 N 个 → 废标表 star=True M 行，覆盖标记页 X/Y」。

当前 v1 基线（三份各配自己的公司文件）：正例 14/18、负例 2/3；★ 对账 0/1、1/10、1/5 页。

## 六、坏行怎么处理（实现口径，`tender/tables.py`）

模型吐出来的行不能照单全收，按两种处理，都留痕：

| 情形 | 处理 | 记在哪 |
|---|---|---|
| 整行都空：关键字段一个没填，且没有出处、没有任何别的内容 | 丢弃，正式表不出现 | `dropped_rows`（含 `missing` 与 `raw` 原始内容） |
| 关键字段缺了，但还有出处或别的字段有内容（如废标行没写条件、但有 p17 的原文引用） | 留下，有 `verdict` 的降成「人工看」，`note` 写「缺字段：x」 | `degraded_rows`（同样记 `missing` 与 `raw`） |
| 空位表只填了表名、格子空着 | 不丢（不是整行空），降级并标「缺字段：field」 | `degraded_rows` |

关键字段：废标 `condition`、评分 `item`、材料 `material`、空位 `form`+`field`、时间 `name`、合同 `item`。
`null` 一律按默认值处理（`""` / `[]` / `人工看`），不因一个空字段让整次运行崩。
这两份记录跟 `tables.json` 一起落盘，另存 `eval/baseline/<doc>/dropped_rows.json`，复核时能对上模型当时输出了什么。

## 七、现状与上面规则不符的四处（已知）

1. **`star` 由模型自填，代码只用正则补一条**。原文标记 2 / 30 / 10 个，表里只有 0 / 1 / 5 行，覆盖标记页 0/1、1/10、1/5。
2. **四张表没有判定字段**：评分、空位、时间、合同的「判得对不对」结构上测不到。
3. **坐标不可靠**：45% 的 refs 没有 bbox；有坐标的里约一半是整页高的框，界面高亮会盖满页，校验段按 bbox 回查也用不上。
4. **串过表**：履约保证金（chongzuo p26 前附表 35）进了废标表，已被负例题抓住。

v2 的对应改法：★/▲ 移到抽取段全文扫一遍并逐条认定语义；六张表统一进中间表示（`Clause` / `Finding`），判定与出处分离；bbox 在解析段就绑到条款级；比对段只吃条款清单和 YAML，不再自己翻原文。
