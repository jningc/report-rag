# 项目优化（面试口述稿）

问题故意收窄：同一批员工题，旧稿/新稿结论变没变。不要把请假、IT、登录、审批堆上去。做成通用知识库，交付物变回聊天框，那才像玩具。

专职写代码的岗看的是：尺子可测、失败能分层、能讲清取舍。不看像不像企业系统。

---

## 一、当时浅在哪

1. **对照比整句。** 抽第一行、去空白、`old != new`。模型写成「可报上限550」和「可报上限 550 元」，业务同一条，尺子当翻转。
2. **评测和生成缠在一起。** 检索 8 题不调 LLM 是对的；影响面 12 题现场打模型，一个「对齐率」里混了检索偏题、第一行不像五种结论、口径真判错。
3. **仓库像脚本。** `chunk_size=100`、冒烟写死本机路径、注释掉的 DashScope。功能少不如这些像玩具。

---

## 二、已经做的（按顺序）

### 1. 结构化短结论

生成仍用 prompt 规定第一行五种结论。对照层 `parse_short_conclusion` 收成 `{kind, amount}`，`conclusions_flipped` 只比这两个槽。

- 代码：`impact.py`（`KIND_*`、`parse_short_conclusion`、`score_flip`）
- 谁判五种：LLM 写第一行；解析器按规则认（拒答 → 可报上限+数字 → 不可报 → 条件分支 → 可报）
- 面试：我不是把 RAG 答得更长，是把「变没变」从比整句改成比字段，避免同义句误报成制度变更。

大片改字仍然用这把尺子：量的是探针题的口径，不是 PDF 像不像。字改了很多、kind/amount 没变 → 不通知。条件分支内部规则变严、两边都是「条件分支」会漏报，要加槽或加探针题，不能退回比散文。

### 2. pytest 钉漏报 / 误报

`tests/test_short_conclusion.py`：通勤第一行多半句、上限带「元」、500→550、餐补可报→不可报；以及「两边都写条件分支 / 上限没数字」对照救不回来。

`python -m pytest tests/ -v`，不要直接 `python tests/xxx.py`。

### 3. 评测分层 + `--offline`

`score_row` 三层：检索落到报销稿、schema（五种 + 上限有数字）、翻转（仅 schema 过才评，否则「未评」）。

```bash
python main.py impact              # 打模型，写 data/impact_last.json
python main.py impact --offline    # 读 JSON 重算，不调 API
```

改解析规则先 offline。面试：生成贵且抖；检索、schema、翻转是纯函数，可以离线回归。

## 四、面试常问

题干按当时原话，不改写成「面试官口吻」。

---

**这是我问的其他 AI 的答案，你觉得呢？**（对方按产品类型分文档型 / FAQ / 流程型 / 对话式智能体；按核心问题分版本冲突、检索不准、知识孤岛、没人用、内容过期；并建议在制度变更上再加「检索召回质量监控」。）

产品形态人人会做，和 ChatPDF 错不开。痛点里「版本冲突 + 口径是否该变」做得少，本仓库已经在这条线上：同一批题打旧库/新库，短结论比字段，产出变了/没变清单。

再加「检索召回监控」不是新模块。`eval.py` 和 impact 里的 `retrieval_ok` 已经覆盖。最多把检索失败和结论翻错拆开讲。不要另起监控产品。

检索不准、知识孤岛、没人用、过期巡检：不做。没有多系统数据、没有真实用户，做成空叙事。Query 改写、混合检索、治理、adoption 冲掉交付物。

---

**先总结我值得做哪些，不值得做哪些。**

值得做：围着「制度改了 → 哪些问答会翻结论」把发布闭环做实。上传新稿就能出清单；探针题当已发布口径；确认后主库切现行版；一屏给财务看该变/不该变、旧结论、新结论、出处。

不值得做：另起检索监控；Query 改写/混合检索/跨部门融合；知识治理去重确权；adoption 埋点；FAQ/流程引擎/再做一个对话壳；自动巡检过期文档（冲击对照已经在回答时效）。评测再加深（金标 exact match、归因拆更细）是测试，不是项目主线。

---

**加深「变更后答案是否该变、变错在哪一层」，这是测试的事吧，我说的是项目，应该让我的项目在面试的时候更有竞争力的。**

对，那是测试。分层评测证明尺子没坏，面试 30 秒带过。

项目竞争力是交付物：谁在用、输入什么文件、输出哪张清单、确认后系统信哪一版。不要靠加 pytest 证明项目变大。下一步加发布闭环，不加更聪明的聊天页、Agent、登录钉钉审批、通用知识库。交付物一回到对话框，项目又变玩具。

---

**财务能用的变更清单会不会场景太小，以及我担心，我的这个预审短结论，解析成 kind 和 amount 也是针对的范围很小。是否是面试项目中值得探索的方向。**

演示域小（报销、限额、餐补）。问题类型不小：权威文本换版后，已经对外说的结论哪些必须重审。HR、法务、产品规则同一类。

面试怕的是「又一个公司内部 ChatPDF」，或只会讲报销讲不出方法。不怕切口小。

`kind` + `amount` 是报销里会改员工做法的最小字段，不是能力上限。请假会换成天数/是否审批/截止日。槽换、流水线不换：定合同 → 生成填 → 解析认 → 两版只比字段。不要把五种结论扩成五十种。值得作为面试项目往下做，但不要靠把场景做大来证明值得。

---

**报销里会改员工行为的，主要就是可否报和限额，两个槽够用。换请假就会变成「天数 / 是否要审批 / 截止日」，槽会换，方法不变：先定业务合同，再解析，再对照。这才是值得探索的方向——答案合同 + 制度版本对照，不是把五种结论扩成五十种。你说的这个怎么搞，说思路。**

方法三步，报销已经走完一遍。探索是把五种结论看成「这个域的合同」，不是再发明通用分类学。

1. 先定合同：只收会改员工下一步的字段。报销 `{kind, amount}`。加槽的唯一理由是不加会漏报（两边都写「条件分支」但规则变严）。依据、长解释不进合同。
2. 生成必须填合同，解析只认合同。Prompt 逼第一行形状；parser 收字段；写了上限没数字 → schema 不过；对照只比字段元组。换请假是换一份 prompt + 一个 parser，不是一个超级解析器。
3. 版本对照：两库同一批探针，只比合同。该变来自读两版制度，不是来自 diff。字改了很多字段没变 → 不通知。漏报只准加探针或加槽，不准退回比散文。

本仓库只做报销：合同写死在一处；金标尽量字段化；清单只展示合同差。请假只停留在口述。

---

**那意思先分析问题属于哪里类合同，然后走对应的合同，是每个问题都要写一个合同？**

不是。合同是一个业务域一份，不是一题一份。

报销共用 `{kind, amount}`。12 道探针都往这两个槽填；限额题有 amount，抬头题 amount 为空。题不同，槽的集合相同。

没有「先分类再路由合同」的日常路径。本项目全是报销，一份 prompt、一份 parser、对照比 `(kind, amount)`。只有报销和请假进同一个入口，才按制度/场景分流一次，仍不是按题写合同。一题一份合同无法对照。

---

**但是这样一个域写一个合同，那太麻烦了吧？这作为我的应聘项目会不会很奇怪，因为这是我自己和 AI 交流出来的需求，并不是真的，面试官会不会觉得我想太多，假需求，没有意义。**

「一域一合同」是为了说明不要做成通用分类器，不是让你再写请假合同。应聘项目仍然只有报销这一份，已经写完：五种结论 + 限额数字。

个人项目几乎都是自拟题。假的是「财务每天在用」；真的是：同一道题两次生成措辞不同，整句一比就像制度变了。做过 RAG 都碰得到。

会翻车：开口「我做了答案合同体系、按域路由」——代码里没有。站得住：「报销改版后住宿 500 变 550，聊天框看不出该通知谁；第一行收成可否报和金额再对照。」对应 `parse_short_conclusion` 和对照表。演示数据自建，README 已写明，面试再说一次。

合同不是项目名或下一阶段功能，只是解释：为什么不 diff PDF、不比对整段答案。

---

**问题是不是太小？**  
小是故意的。错账发生在员工按旧限额填单，不是制度有 200 页。工程做在对齐、评测、串稿隔离。做大成知识库，交付物变回聊天框。

**为什么两个索引不 metadata 过滤？**  
防串稿。旧答必须只来自 v1.2 文件。

**为什么按页切、不跨页？**  
出处要落到页。代价是 chunk 可能过碎。

**为什么先拒答再生成？**  
相关度不够不调 LLM：省钱、防编造。`eval.py` 与 `MIN_RELEVANCE_SCORE` 共用。

**和文档 diff / 预审机器人什么区别？**  
diff 比字，字变了答案未必变。预审拦这一张单；影响面决定改版日通知哪几条口径。探针题是口径资产，不是测试集。漏报只准加探针或加槽，不准退回比散文。

**结构化短结论谁说了算？**  
模型选标签，规则认标签。认错是生成；以前 `str != str` 是尺子错。pytest 把同义句误报钉死。
