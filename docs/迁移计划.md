# tender-lint 迁移计划：从「五节点直排」到「四段流水线」

> 配套文档：`docs/招投标核对方案.md`（为什么这么改）、`docs/架构对比.html`（两种流程的可视化）。
> 本文件只回答一个问题：**接下来按什么顺序、每一步做到什么算完。**

## 0. 目标与不动的东西

**外壳不动**：`main.py` 命令行、`app.py` 页面、六张表（废标 / 评分 / 材料 / 空位 / 时间 / 合同）、提问框，全部保持现在这套。

**只动内核**：把 `tender/workflow.py` 里五根并排的管子（`feibiao / pingfen / cailiao / kongwei / aux`，各自检索、各自出表），接成**解析 → 抽取 → 比对 → 校验**四段，段与段之间只传 JSON。

**每阶段硬门禁（不满足不进下一阶段）**：三份样本 `check` 通过 + 8 题分数不低于上一阶段 + 页面能开。任一不过就停。

## 1. 架构：现在 → 升级后

```
现在（workflow.py 实况）          升级后
──────────────────────────      ──────────────────────────
PDF ─┐                          PDF → [解析] → 章节树+表格+坐标
索引 ─┼→ feibiao ─┐                       ↓ JSON
YAML ─┘  pingfen  ├→ aux → 六张表        [抽取] → 条款清单（检索只在这里）
         cailiao  │                       ↓ JSON
         kongwei ─┘                      [比对] → 差异清单（只看条款+YAML）
         每个节点自己 index.search        ↓ JSON
         共享 State，原文读 4 遍          [校验] → 通过/退回（只看证据）
                                          ↓
                                        核对报告（渲染层出六张表）

                                     规则库 ──注入→ 抽取 / 比对
                                     回归门禁 ←─ 题集全量重跑 ←─ 归因
```

- 废标 / 评分 / 材料 / 空位**不删**，收进「比对」段，变成差异清单的四个分类。
- `tables.py` 的六张表降级为**渲染层**（`render_*` 从 `Finding` 映射回来），不是契约。
- 检索从 5 次节点内搜，收成**全文只检索一次**（按章分组），收敛在抽取段。

## 2. 四段 JSON 契约（动手前先手写样例）

拿 `sample/beijing_road.pdf` 第 8 页「投标保证金 8000 元」手工走一遍，四份产物都写出来当契约样例，再落成代码。

| 段 | 产物 | 每条至少有 |
|---|---|---|
| 解析 | `ParsedDoc`：章节树 + 表格 | 页码、bbox；**单元格和表头绑在一起**（跨页表用表头接续） |
| 抽取 | `Clause`：条款清单 | 类型（废标/评分/材料/空位/金额/兜底）、原文摘录、页码、bbox；**同一条保证金的多处出现要能串起来**（先做同页/同类型归并，跨页实体对齐后置） |
| 比对 | `Finding`：差异清单 | 只含 符合 / 偏离 / 缺失，`evidence` 指回 `Clause` 的页码，并**注明落到哪张表** |
| 校验 | `Verified`：通过或退回 | 退回原因**指向某一条条款**（`reason: 'c_002 原文该 bbox 无金额'`），不指向「表里有个空」 |

落地：`tender/contracts.py` 定义这 4 个 dataclass + 测试断言「**无 bbox 的条款不放行进下一段**」。契约冻结后不再改。

### 抽取段样例（示意）

```
输入：检索返回的 hits（page/bbox/text）
输出：
{"clauses": [
  {"id": "c_001", "page": 8, "bbox": [120.5, 340.2, 480.0, 385.7],
   "type": "金额", "text": "投标保证金金额：01 包 8000 元"},
  {"id": "c_002", "page": 17, "bbox": [90.1, 210.4, 450.3, 260.0],
   "type": "废标条件", "text": "未缴纳投标保证金的投标被否决"}
]}
```

抽取只做「这段原文在讲什么、归哪一类」，**没有 verdict、不对照公司**。

### 比对段样例（示意）

```
输入：Clause 列表 + company.yaml
输出：
{"findings": [
  {"clause_id": "c_001", "verdict": "满足",
   "evidence": {"page": 8, "chapter": "招标公告", "text": "可采用银行保函"}}
]}
```

比对只做「拿公司情况给每条下结论」，不拿索引、不翻 PDF。

### LLM 位置（改造前后不变）

| 段 | 干什么 | 调 LLM |
|---|---|---|
| 解析 | PDF 转章节树 + 表格 + 坐标 | 否，纯解析 |
| 抽取 | 找条款、归类、判假朋友 | **是** |
| 比对 | 对 YAML 出 符合/偏离/缺失 | **是** |
| 校验 | 按 bbox 回查原文 | 否，纯机械 |

打分只发生在流水线**外面**（`eval/compare.py` 三档 hit/miss/absent），不在流水线里。

## 3. 阶段与顺序

| 阶段 | 工期 | 做什么 | 完成标准 |
|---|---|---|---|
| **0 冻基线** | 0.5 天 | 三份样本各跑一次 v1，六表 + `render_tables` 文本存 `eval/baseline/<doc>/`（`data/` 不进 Git，基线要进 Git 才对得上历史）；**每份 PDF 配自己的公司文件**（meta 记 `company` 与 `company_sha256`，公司一改就等于换题）；题集重写为 21 条（正例 18 / 负例 3，5 条断言判定值，每条附原文摘录）；★/▲ 原文标记数另存 `eval/markers.json` 做对账；`compare.py` 按「表 + 关键词 + 页码 + 判定」判并可输出 JSON | 基准文件齐；v1 得分 正例 15/18、负例 2/3；★ 对账 0/1、1/10、1/5 页；人工复核清单在 `eval/题集核对清单.md` |
| **1 定契约** | 1.5 天 | 先手写 p8 四份 JSON 样例 → 落成 `tender/contracts.py`（`ParsedDoc/Clause/Finding/Verified`）→ `tests/test_contracts.py` 断言「无 bbox 不放行」 | 三份样本的现有输出能转成契约对象并校验通过；契约冻结 |
| **2 拆四段（行为等价）** | 3 天 | `tender/stages/{parse,extract,compare}_stage.py` + `workflow_v2.py`。检索从 5 次改成**按章分组 1 次**（沿用现有 query 和 k，先不新写）；`_follow` 收进 extract；`compare` 复用现有 verdict；`tables.py` 降级为渲染层，界面与 Excel 不动；★/▲ 由抽取段全文扫一遍并逐条认定，不再在废标节点里顺手补一行 | v2 与 v1 逐条 diff：内容一致或更好；21 题不低于基线（正例 15/18、负例 2/3）；★ 对账行数与标记页覆盖分别高于 0/1、1/10、1/5；`app.py` 能切引擎 |
| **3 回归门禁（提前做）** | 1 天 | `eval/run_regression.py`：跑三份 → 21 题 + 注入变体 → 读 `compare.json` 输出 `{regression, rules, repeat_error, markers}`，比上次掉就 exit 1（★ 对账行数变少也算掉） | 故意改坏一条规则，门禁必须红 |
| **4 校验段** | 2 天 | `verify_stage.py`：只做机械回查——页码存在、bbox 原文含抽取值（数值归一 8000/8,000/捌仟）、交叉引用落到正确章。**不调模型判「合理性」**。把 3 个已知幻觉写成 `eval/hallucination_cases.json` | 3 案例全拦住；正常行被误退 <10%（用 21 题统计） |
| **5 规则库 + 每段可单独重跑** | 2 天 | `tender/rules.py`：`Rule{id, trigger, action, scope(extract/compare)}` 存 git 里的 `data/rules.yaml`。先放两条：①术语同义（注册建造师 / 一级建造师）；②互斥（投标保证金 ≠ 履约保证金）。抽取、比对读库，解析、校验不读。`step_out.py` 落盘 `data/step_output/<doc>/v2/*.json`，并支持只重跑某一段 | 删规则分数掉、加回分数涨——两次跑动就是机制证据 |
| **6 扩题 + 三轮数字** | 2.5 天 | `eval/inject.py` 最小版（改保证金金额、删/加 ★、正文与前附表冲突、条款挪章），6 种 × 3 样本 + 21 原题 ≈ 39 条；跑三轮（v2 无规则 / 首次规则后 / 最终），写一篇「退化 → 回滚」记录 | 三个指标齐全，数字进文档，不编 |
| **7 收尾** | 1 天 | 更新 README（引擎开关、门禁命令）、`docs/招投标核对方案.md` 的「现状」段、`docs/架构对比.html` 补 v2 落地标记 | 文档与代码不含过期说法 |

合计约 13.5 天，对得上两周排期。

## 4. 门禁与「能单独重跑」

- **每段产物落盘**：`data/step_output/<stem>/v2/{parse,extract,compare,verify}.json`（复用现有 `tender/step_out.py` 的目录）。这就是「可观测」。
- **单段重跑**：调 bug 时只重跑某一段，不重跑全文。
- **页面进度文案改成四段**：`app.py` 的进度回调从「废标/评分/材料/空位」改成「解析/抽取/比对/校验」。
- **门禁红了 = 阻塞**（阶段 0–6）：任一阶段做完门禁必须绿才算完，红了先回滚/修；阶段 7 收尾和文档那步按警告。

## 5. 必须新写 vs 直接复用

| | |
|---|---|
| **新写** | 表格结构识别（现在 `parse.py` 只有文本块，没有表格，「01 包 / 8000 元」分两行就是这么来的）；`Clause` 中间表示；校验段；规则库；`inject.py` |
| **复用** | `Ref` 的 page/bbox 语义、4 值 verdict、`_follow` 的引用跳转、`step_out.py` 分步落盘、`compare.py` 打分逻辑、`app.py` 进度回调 |

## 6. 四个最容易翻车的点

1. **别把 `tables.py` 当契约用**。它是最终输出格式，契约是中间 JSON；混在一起就变成四段还是围着表格转。
2. **检索 5 次变 1 次会掉召回**。v2 阶段只许重组、不许改 query，先用 diff 证明等价，再谈优化。
3. **表格识别是无底洞**。这一轮只做「跨页表用表头接续」一条，且只针对两列值型表，别碰复杂合并表。
4. **校验段用模型判「证据充分」会引入第二个幻觉源**。只做机械回查；判不了的统一「人工看」。

## 7. 已定决策

- **v1 留**：保留 `--engine v1` 到第 6 阶段结束，出数字时要用它做对比；之后作为回退引擎保留。
- **规则库进 git**：规则是可审的领域知识，不进 git 就没法回滚。`data/rules.yaml` 随代码提交。
- **门禁红了怎么办**：阶段 0–6 按**阻塞**写——红了就停，先回滚/修，修绿了才进下一阶段；阶段 7（收尾）和文档那步按**警告**——红了只在报告标出，不挡收尾。

## 8. 本轮不做

题集扩到 24、再去收 20–30 份招标文件——放在管子和门禁都稳定之后。填投标文件、检查投标草稿、OCR、Word，按方案继续不做。
