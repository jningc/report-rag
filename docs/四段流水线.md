# 四段流水线（阶段 2）

目标只有一个：**在输出等价的前提下，把「五个平行节点」拆成「解析 → 抽取 → 比对 → 校验」，段间只传 `tender/contracts.py` 的模型。** bbox 条款级化、★ 全章扫描、抽/比真正分离都**不在这一轮**——一次只改一个变量。

## 一、四段与文件

| 段 | 文件 | 输入 → 输出 | 调模型 |
|---|---|---|---|
| 解析 | `tender/stages/parse_stage.py` | PDF → `ParsedDoc`（章节树 + 页码；`tables` 暂空）+ 索引对象 | 否 |
| 抽取 | `tender/stages/extract_stage.py` | `ParsedDoc` + 索引 + company → 六表行 + `Clause` 清单 + 坏行记账 | **是**（每表一次，提示词照旧） |
| 比对 | `tender/stages/compare_stage.py` | `Clause` + 行里的 verdict → `Finding`（落表、类型一致、证据带上） | 否（结论仍由抽取调用一并给出） |
| 校验 | `tender/stages/verify_stage.py` | `Finding` → `Verified`（阶段 2 只查页码存在，`enforce=False`） | 否 |

入口：`tender/workflow_v2.py: run_check_v2()`，返回与 v1 **同形状**的 dict，所以 `render_tables`、`app.py`、`main.py`、`eval/compare.py` 一行没改。

每段产物落盘到 `data/step_output/<stem>/v2/`：

```
parse.json              章节树 + 页码（ParsedDoc）
extract.clauses.json    能进契约的条款
extract.rejects.json    进不去的行 + 原因（没框、没原文、类型不对）
compare.findings.json   结论 + 落表
compare.rejects.json    落错表/契约不成立
verify.verified.json    每条结论的页码回查结果
```

## 二、怎么切换

```bash
# 命令行
python main.py check sample/beijing_road.pdf sample/beijing_road_company.yaml --engine v2
# 环境变量（页面、app.py 都认）
TENDER_ENGINE=v2 python main.py web
```

默认仍是 v1；写错的值回退 v1，不抛异常（`tender/engine.py`）。

| 东西 | 现状 |
|---|---|

| bbox | 原样透传，条款级框占比不变（47% / 53% / 58%） |
| ★/▲ | 仍在废标节点的检索范围内找、只补一条；全章扫描留到单独一轮 |

## 五、这一轮暴露的真问题：单跑分数不可信

同一份 wenling，同一引擎、同一索引、同一天：

| 什么时候 | 正例 |
|---|---|
| 冻基线（19:17） | 5/5 |
| 我手动跑 v2 | 4/5 |
| 门禁正式跑 v1 / v2 | 3/5 / 3/5 |

**差两题，全是模型抖动**——行数也在 68↔77 之间漂。结论：

1. 「不低于基线」不能拿单跑比分，否则拆段这种没改行为的改动也会被判红（或反过来，真改坏了也可能碰巧不红）；
2. 阶段 3 的门禁必须**同一版本跑 N 次取多数**，并把来回翻的题标成 `flaky`，不参与判红；
3. 简历/文档里的数字要写区间或中位数，不写单次最好成绩。
