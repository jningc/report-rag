规则库
结构化：触发条件 + 动作。不是「心得体会」。
注入 抽取
注入 比对
原文只读 1 遍；后一段只信前一段的格式，不回头翻 PDF；错了能指到具体一段。
跑完一轮→ 人工确认错误→ 归因到某一段→ 提炼规则→ 注入→ 题集全量重跑→ 涨 = 生效/ 掉 = 回滚
上面这条回边，就是「自进化」；没有最后的重跑，前两步都能造假。

同一个例子，走两条路

样本：sample/beijing_road.pdf，第 8 页（投标人须知资料表 12.1）
投标保证金金额：01 包：8000 元；可采用下列形式之一：(1) 保函（推荐）(2) 支票 (3) 汇款
「投标保证金」这份文件里出现五次，五个角色（下面页码都已对着 PDF 核过）：
p8 · 金额 + 三选一形式 + 不予退还情形 p17 · 交纳规则（未按要求缴纳 → 投标无效） p25 · 资格审查表里的要求 p27 · 围串标情形 p79 · 格式章：交款单据空位 p83 · 投标书模板里的「履约保证金」（另一个东西）
现在：五个节点各搜各的
废标节点搜到 p17，收一行「未按要求缴纳 → 无效」；
材料节点搜到 p79，收一行「交款单据」；
空位节点翻格式章，撞上 p83 的「履约保证金」也照收。
四张表里四条「保证金」，页码不同、口径不同，没有一处说明它们同源。
假如 p8 那张两列表格切块切歪了（「01 包」和「8000 元」被切成两行没对齐），表里就是个空值。
你只知道「图里有个空」，不知道是解析错了、检索没召回到 p8、还是模型没抽出来。
升级后：一条数据走四段
01 解析：p8 那段落成条目 {page:8, bbox, text:"01 包：8000 元"}，表格和表头存在一起。
02 抽取：全文只检索这一次，五处按类型归位（金额 / 程序 / 资格 / 围串标 / 格式空位），并判掉 p83 那条「履约保证金」。
03 比对：拿 company.yaml 的「能否交保证金」对，结论「满足」；p83 那条归到合同要点，不进废标表。
04 校验：逐行回查——这一行的页码 + bbox 里，原文真写着「8000 元」吗？
校验会把 p17 那条退回去：它的原文只说「按规定金额交纳」，没写金额，拿它当金额行证据不足。
错误被钉在「抽取段这一条」上，不是「表里有个空」。

所以四段拆开换来的不是「更准」，是错了能说是哪一步错的；再配上规则库和重跑，同类错才不再犯第二次。

两者的差别

现在升级后
切分轴按问题：废标 / 评分 / 材料 / 空位按阶段：解析 / 抽取 / 比对 / 校验
节点之间共享 State，各取原文显式 JSON 契约，只拿上一段产物
原文读几遍4 遍1 遍
检索次数4 次，每个节点自己搜1 次，收敛在抽取
节点依赖平级，可任删串行，后段信任前段格式
校验无独立一段，只看证据
主循环直线直线 + 进化回边
外部接口不变：输入 PDF + company.yaml，输出六张表 + 提问框

原来那四个节点不会消失：它们沉到「比对」段里面，变成差异清单的四个分类。所以不是推翻重写，是把四根并排的管子接成一根，中间加一道复核。
