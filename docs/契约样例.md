# 契约样例：p8「投标保证金 8000 元」走一遍四段

阶段 1 的产物不是代码，是**先手写这四份 JSON，再让代码去符合它们**。顺序反过来就会写出一堆没人用的字段。

代码在 `tender/contracts.py`，样例在 `eval/contracts/samples/`（`pytest tests/test_contracts.py` 会校验这几个文件，样例改坏了测试会红）。

---

## 零、原文（`sample/beijing_road.pdf`，物理页 8）

```
12.1 投标保证金
投标保证金金额：01 包：8000 元；
投标保证金可采用下列形式之一：(1) 金融机构或担保机构出具的保函（推荐）(2) 支票 (3) 汇款
注1 投标人应以出具保函（保险）形式提交投标保证金，供应商无法出具保函（保险），确需银行转账、
    支票等方式缴纳保证金的，应向代理机构提供情况说明（格式自拟）。
```

同一份文件里「未按上述要求缴纳投标保证金的，其投标无效」在 p17；「履约保证金」只在 p83 的投标书模板里，跟这笔钱不是一个东西。

## 一、解析段 → `ParsedDoc`

纯解析，不调模型：章节树 + 表格结构 + 页码坐标。**表头和单元格绑在一起**，跨页表用 `continued_from` 接上页。

```json
{
  "pdf": "sample/beijing_road.pdf",
  "page_count": 92,
  "page_numbering": "physical",
  "sections": [
    {"type": "invite", "title": "第一章 投标邀请", "start_page": 3, "end_page": 6},
    {"type": "notice", "title": "第二章 投标人须知", "start_page": 7, "end_page": 22}
  ],
  "tables": [
    {"page": 8, "bbox": [47.0, 340.0, 548.2, 400.0],
     "header": ["包号", "投标保证金金额"],
     "rows": [["01 包", "8000 元"]],
     "continued_from": null}
  ]
}
```

> 现状说明：v1 没有表格识别，这张表是**目标态**。v1 把「01 包」和「8000 元」抽成两行文本，「8000」和「01 包」对不上号就是这么来的。

## 二、抽取段 → `Clause`

只回答「这段原文在讲什么、归哪一类」，**不下结论、不对照公司**。每条必须带一处主出处（页 + 四数框 + 原文），`follow_reference` 补的出处放 `extra`。

金额那条（`p8_clause_amount.json`）：

```json
{
  "id": "beijing_road:notice:12.1",
  "type": "废标",
  "text": "投标保证金金额：01 包：8000 元；未按上述要求缴纳投标保证金的，其投标无效",
  "evidence": {"page": 8, "bbox": [47.0, 37.3, 548.2, 804.3],
               "text": "12.1 投标保证金 投标保证金金额：01 包：8000 元",
               "chapter": "第二章 投标人须知", "clause": "12.1"},
  "extra": [],
  "section_type": "notice",
  "star": false,
  "value": "8000 元",
  "source": "model"
}
```

形式那条（`p8_clause_form.json`）：主出处是 p8 注1 的**条款级框** `[65.8, 377.1, 562.2, 696.5]`，`extra` 挂 p17「12.2 交纳形式」的跳转结果，`source: "follow"`。

两条的区别就是这一阶段唯一的看点：**金额那条的框高 767pt，是整页框**——`is_clause_level()` 判它不合格，`evidence_ok()` 返回 False。这不是样例写错，是现状照抄。

## 三、比对段 → `Finding`

拿 `Clause` + `company.yaml` 出结论，**落哪张表在这一段定死**（`clause.type` 与 `finding.table` 必须对得上，`table_matches()` 检查）。

```json
{
  "clause_id": "beijing_road:notice:12.1",
  "table": "废标对照",
  "verdict": "不满足",
  "evidence": [{"page": 8, "bbox": [47.0, 37.3, 548.2, 804.3], "text": "12.1 投标保证金 投标保证金金额：01 包：8000 元"}],
  "note": "company.yaml: deposit_ready=false"
}
```

这一段的输入里没有任何 PDF、没有索引——它只信条款清单。

## 四、校验段 → `Verified`

只做机械回查（页码在不在、框里原文含不含抽出来的值、交叉引用落到哪章），**不判「合不合理」**。退回必须指到具体一条。

```json
{
  "finding_id": "beijing_road:notice:12.1",
  "ok": false,
  "checks": [
    {"name": "page_exists", "ok": true, "detail": "第 8 页存在"},
    {"name": "text_contains", "ok": true, "detail": "该页文本含「8000 元」"},
    {"name": "cross_ref_section", "ok": true, "detail": "12.1 属投标人须知"}
  ],
  "reject_reason": "beijing_road:notice:12.1 的 bbox 高 767pt（整页框），定位不到 12.1 那一行，不能当正式出处"
}
```

形式那条则是通过的（`p8_verified_pass.json`，三条 check 全 ok、`reject_reason` 为空——写了解释反而会报错）。

## 三条硬规矩（写在 `contracts.py` 里，不写在提示词里）

| 规矩 | 怎么落地 |
|---|---|
| 没有框的条款不放行 | `Evidence` 的 `bbox` 必须四数、面积大于零；`Clause.evidence` 必填 |
| 整页框不算定位 | `is_clause_level()`：框高 ≤ 页高 60%；`evidence_ok()` 供进段前拦一道 |
| 段间只传 JSON | `ParsedDoc → Clause → Finding → Verified`，下游不回头翻 PDF |
| 页码一律物理页 | `ParsedDoc.page_numbering` 固定 `physical`；印刷页由渲染层换算 |
